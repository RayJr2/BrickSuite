## Live updater and publication mechanics

Released Windows v0.3.0 clients fetch:

`https://raw.githubusercontent.com/RayJr2/BrickSuite/master/deployment/update/update.json`

This is the tracked file on **master**, not a tag or GitHub Release asset. A push
changing that file changes live updater content as GitHub/caches refresh. The
updater adds a cache-busting query. M40.5A leaves its bytes, version/date, and URLs
unchanged at v0.3.0. Do not advertise 0.4.0 before downloadable public assets exist.
No updater download/checksum/install feature is added.

`.github/workflows/macos-artifacts.yml` is **workflow_dispatch only**. Dispatch on
an approved ref and verify its recorded `SOURCE_SHA` equals the release SHA;
checkout explicitly uses `github.sha`. Keep that ref pinned while dispatching.
The workflow uploads Actions artifacts, not a public GitHub Release.

`.github/workflows/publish-help.yml` automatically deploys Pages on master pushes
changing `resources/help/**` or that workflow, and supports manual dispatch.
M40.5A does not change either, so its push alone will not publish Help. Inspect
pending commits for Help changes before pushing. Dispatch Help deliberately at
publication time; no automatic trigger was changed here.

Public GitHub metadata independently confirmed `master` as the default branch
and `BrickSuite v0.3.0` as the previous release title on 2026-10-07.

Existing tag convention: `v0.1.0`, `v0.2.0`, `v0.3.0`; recommended tag **v0.4.0**.
Recommended release title: **BrickSuite v0.4.0**.

   separate Apple Silicon/Intel ZIPs (no Universal2), Ubuntu baseline tarball.

   [macOS](../deployment/macos/README.md), or

   `./install.sh` → approve prerequisites if needed → launch `bricksuite`.

   preparation and fit readiness are model-specific. Calibration records physical
   observations and Verified evidence; nominal output applies no Fit Profile.

   - macOS builds are ad-hoc signed and are not Apple notarized. The project has
     no Apple Developer ID certificate; macOS may require first-launch confirmation.
   - The Intel macOS package is GitHub Actions built and CI-validated; manual
     Intel runtime acceptance remains pending.
   - Remote Clients cannot execute direct Set part-out. Uncertain nested
     composition can block part-out until the required composition is established.
   - Difficult LDraw topology may require external repair. BrickSuite does not
     claim universal printability.
   - Verified Fit corrections apply only where supported evidence, interface,
     compatible profile, and print orientation permit. Repaired geometry does
     not automatically gain fit ownership.
6. **SHA-256:** insert four final hashes and attach checksum files. Historical
   pre-cutover hashes above are never final checksums.
7. **Help / Support:** [User Guide](https://rayjr2.github.io/BrickSuite/), built-in
   Help, and [Support BrickSuite with PayPal](https://www.paypal.com/ncp/payment/WB8RKBVN6DTYW).
   Support is optional and unlocks no features or services. BrickSuite does not
   process payments. No tracking parameters.
